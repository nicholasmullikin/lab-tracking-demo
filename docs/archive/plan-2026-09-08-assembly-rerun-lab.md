## Scope and success criteria
- Optimize for the selected one-week / 15–25 hour budget: one continuous tracker, one static-view hand baseline, the shared Rerun review surface, and only then strictly time-boxed exploratory trials.
- Replace the prior end-to-end “mini-Transfyr” ambition with a perception-method lab first.
- The primary experiment input is one pinned, synchronized three-minute Assembly101 segment across an RGB static view and a monochrome ego view. The unified Rerun recording, normalized artifacts, and method ledger are the deliverables; a screen recording is optional and not a goal.
- A method counts as working only when it: (1) completes inference over its declared full-duration target view set, (2) retains its unmodified native artifact, (3) produces a validated normalized artifact, (4) appears on the shared Rerun timeline, and (5) records runtime, peak VRAM, source commit, checkpoint, and license. A 10–20 second window is only an installation/smoke-test gate.
- Do not train, fine-tune, annotate, build a downloader/orchestrator pipeline, or claim benchmark accuracy in this phase. Use ground truth only as an optional visual reference, not as an evaluation project.

## AI ownership and hard human gates
- **AI-driven work:** an agent may independently create the project scaffold, isolated runner wrappers, schemas, normalization code, Rerun Blueprint, fixture tests, profiles, method ledger drafts, and comparison notes. It may run the approved method/clip matrix once each item is pinned and record logs and failures.
- **Human gate — G1: data and story.** Before downloading or running real clips, personally approve the exact three-minute Assembly101 sequence segment, source-frame offset, RGB static primary view, monochrome ego stress-test view, per-toy part/action vocabulary, and stated purpose. The agent can propose candidates from metadata but cannot infer which footage best illustrates a meaningful manipulation or whether its use is appropriate for the intended presentation.
- **Human gate — G2: experiment contract.** Approve the canonical prompts, object count, resolution, initializers, and comparison statement before core inference. Changes after an unexpected result create a new named run; the agent must not silently tune a prompt or threshold until a result looks better.
- **Human gate — G3: core semantic visual QA.** Once the MuggledSAM + MediaPipe core spine exists, inspect its fixed two-timestamp contact sheet and raw-clip/Rerun overlays. Accept it only if labels, coordinate frames, identity behavior, and time alignment mean what the method cards say they mean. Exploratory methods receive a ledger review, not a new gate. Schema validation is necessary but cannot establish semantic correctness.
- **Human gate — G4: stop/re-scope.** The agent stops and requests a decision when an adapter exceeds its stated timebox, needs upstream-source modification rather than a thin wrapper, OOMs after one reduced-resolution retry, needs a new license/access request, produces output that is visibly misaligned, or cannot build and execute its CUDA/native extensions against cu128+ on the RTX 5070 Ti (`sm_120`). It records the failed state and does not hero-debug or substitute a different method without approval.
- **Human gate — G5: claims and presentation.** A human approves every performance statement, all use of ground truth, the “works/fails” conclusion, and source/model licensing before sharing any Rerun recording, screenshots, or optional screen capture. The agent may describe measured runtime and VRAM; it must never convert visual quality into an accuracy claim without a completed evaluation protocol.

## Project foundation
- Initialize Git and the `.gitignore` before code; exclude `data/`, `runs/`, model caches, source recordings, canonical proxies, and Rerun artifacts. Create a typed Python 3.12 project centered on [pyproject.toml](../../pyproject.toml), `uv`, a pinned `rerun-sdk`, Ruff, pytest, and a concise [README.md](../../README.md). The shared environment contains only the common manifest, normalization, profiling, and Rerun-export code.
- Keep external research repos isolated and unmodified. Define their clone paths, URL, pinned revision, required Python/CUDA/Torch environment, model checkpoint, citation, and license in `configs/methods.yaml`. Point MuggledSAM and WiLoR entries to their existing known-working interpreters, `~/.pyenv/versions/muggled_sam` and `~/.pyenv/versions/wilor`; exploratory environments remain isolated and must pass the cu128+/`sm_120` build gate. One invocation should process the approved batch of chunks/views to avoid reloading a model for every chunk.
- Add `configs/clips/assembly101_comparison.yaml` to pin one three-minute sequence segment, two synchronized views, per-toy fine-grained part/action vocabulary, prompts, and a short smoke window near the start. Declare all three clocks: 60 FPS source video, 30 FPS analysis proxy/annotations, and 60 FPS optional hand-pose reference. Require an even `source_start_frame` and store the exact mapping `analysis_frame i → source_frame source_start_frame + 2i`, annotation-frame offset, and pose-frame offset in the manifest.
- Fetch the complete approved recordings before trimming: one static RGB recording is about 825 MB, while static plus ego is roughly 860 MB. Record the resolved `cvml-nus/assembly101` revision, source-file hashes, and exact `ffmpeg` trim/transcode command. Its output is the canonical three-minute 30 FPS, 8-bit `yuv420p` H.264 proxy per view; adapters consume that proxy rather than independently decoding and resizing raw footage. Do not reuse wet-lab prompts: this data contains vehicle parts and assembly actions.
- Establish ignored artifact locations: `data/` for the fetched subset and cached proxies, and `runs/<clip>/<method>/<run_id>/` for native outputs, normalized JSON/NPZ, profiles, logs, and Rerun recordings. Cache/reuse a run only when its fingerprint matches `method revision + checkpoint + prompts + resolution + clip/view + chunk policy`; otherwise create a new run ID. Add `SOURCES.md` and `LICENSES.md` for dataset/model/repo provenance and non-commercial constraints.

## Common interchange contract and Rerun viewer
- Define versioned Pydantic models in `src/battle_lab/schema.py`: `ClipManifest`, `RunManifest`, `FrameObservation`, `InstanceTrack`, `HandPose`, `CameraPose`, and `MethodStatus`. Every observation carries an original-video timestamp in nanoseconds, source camera ID, native-coordinate metadata, confidence when supplied, and a pointer to its native artifact.
- Implement one adapter interface in `src/battle_lab/adapters/base.py`: `prepare`, `run`, `normalize`, and `validate`. Adapters must preserve model-specific meaning rather than inventing comparability—for example, WiLoR’s camera-relative 3D hand joints remain explicitly non-metric, while Kineo’s world-space pose remains distinct.
- Build `src/battle_lab/rerun_export.py` to produce one `comparison.rrd` per clip. Log each encoded source-video asset once, use common timestamps, and separate entity roots such as `/methods/muggled_sam/...`, `/methods/wilor/...`, and `/methods/kineo/...` so layers can be enabled, hidden, or inspected independently.
- Keep points and boxes at the full 30 FPS analysis cadence, but log segmentation masks at a declared default of 5 FPS (every sixth analysis frame). Record the mask cadence and sampling rule in the `RunManifest`; preserve full-cadence native masks under `runs/.../native/` or `runs/.../normalized/`, outside the `.rrd`.
- Make Rerun export inference-free: it consumes indexed normalized artifacts, so an overlay, cadence, Blueprint, or comparison change can regenerate the `.rrd` without rerunning a model.
- Ship a programmatic Rerun Blueprint: synchronized ego and static 2D views with masks/boxes/keypoints, with the color static view visually designated as primary and the monochrome ego view as a stress test; add a 3D world view only for methods that truly provide 3D coordinates. Include a time-series panel for confidence/track count/latency/VRAM and a text panel containing the run manifest and known limitations. This reuses Kineo’s existing Rerun-oriented output design in `/home/nick/src/kineo/kineo/pipeline/stages/rerun_export.py`, but exports all methods through this repo’s common contract.

## Experiment protocol and 16GB operating rules
- Use a three-tier execution policy to protect iteration time: (1) a 20-second, one-view, 480p smoke run for setup and schema; (2) a three-minute RGB static-view 720p candidate run after smoke passes; and (3) the required full-duration target view set only after human acceptance. MuggledSAM’s core target is both views; MediaPipe’s is the RGB static view. Exploratory methods may stop at tiers 1–2 and are labeled accordingly.
- Use the exact same three-minute manifest for every accepted method. Select it to contain both an easy manipulation interval and a deliberately difficult interval (occlusion, similar parts, or fast manipulation); the full segment is the comparison unit, while the fixed 10–20 second smoke window only proves an integration before a long run. Perform all core analysis on the declared 30 FPS proxy, preserving mappings to source/annotation/pose clocks.
- Make continuity and chunking adapter capabilities, not a global protocol: streaming trackers run continuously and checkpoint state/output at a declared interval, while per-frame methods may process stateless batches. The run manifest must state `continuous`, `checkpointed`, or `reinitialized`, plus why; chunk-boundary ID resets are only meaningful for methods that do reinitialize.
- Run one GPU process at a time. Default to the cached 720p proxy, method-specific downscaling, batch size one, bounded object count, and process teardown only when switching methods. Log GPU name, compute capability, driver, CUDA/Torch versions, peak allocated VRAM, peak `nvidia-smi` usage, wall-clock throughput, total full-duration runtime, and failure/OOM details.
- Measure cold start and warm-run time separately. Trial FP16/autocast, `torch.compile`, or a larger chunk only on the smoke/candidate tier; retain an optimization only when it lowers measured full-run wall time without exceeding the 16GB guardrail or introducing additional ID resets.
- Profile at native settings and at the canonical reduced-resolution setting where feasible; do not compare raw FPS as accuracy. The comparison result is an auditable method card with output type, setup friction, VRAM, throughput, coverage, and observed failure cases.
- Treat setup as failed—not as an invitation to rewrite vendor code—when any adapter misses its timebox. Store `blocked` or `failed` in [docs/method-ledger.md](method-ledger.md), including the reproducing command, logs, hardware state, and next prerequisite.

## Pre-accuracy success measures
- **Full-duration coverage:** per method and declared target view, report `frames_with_normalized_output / total_target_frames`, the first and last covered timestamp, and every gap longer than one analysis-frame interval. A core method needs 100% target coverage or an explicit `smoke_only`/`partial` status—never an implied full pass.
- **Time to first usable output:** measure wall-clock time from invoking a runner to the first validated normalized observation appearing in Rerun on the smoke window. This captures install/inference/adapter friction without conflating it with the full run.
- **Peak VRAM and total runtime:** record device-visible peak VRAM and wall-clock duration for the complete declared target view set. Store both in the run manifest and method ledger; do not derive one from the other.
- **Chunk-boundary ID resets:** report `explicit_or_observed_ID_resets / chunk_boundaries` separately for each method and view, including whether the reset was required by the upstream tool or caused by lost tracking. Do not aggregate resets into a generic quality number.
- **Fixed human QA:** review exactly two pinned timestamps per completed method—one easy manipulation and one hard/occluded manipulation—and record `pass`, `flag`, or `fail`, plus a one-sentence reason. This is a repeatable semantic sanity check, not a substitute for accuracy evaluation.
- The agent generates the same two-timestamp contact sheet for every method before G3, including raw frame, method overlay, coverage/chunk state, and a link to the native artifact. This makes the human decision a short, comparable review rather than a timeline-search task.
- These five measures are the phase-one scorecard. Do not add mAP, HOTA, J&F, hand-pose error, or TAS F1 until the user explicitly approves the data/annotation and evaluation protocol required to make those numbers meaningful.

## Three-minute input protocol
- The Rerun recording covers one continuous three-minute Assembly101 segment, with a trimmed 30 FPS `yuv420p` H.264 proxy logged once per view rather than individual full-resolution frames. Store source-video identity, trim offset, exact ffmpeg command, and source-to-analysis clock mappings in the run manifest.
- Rerun is a review surface, not a full-fidelity mask archive: log points and boxes at full cadence, log masks at the declared 5 FPS cadence, and keep full native masks in the corresponding run artifact directory. The text panel displays this cadence so viewers do not mistake visual sparsity for missing inference.
- Record RRD export time and file size in the method ledger. If opening or time-scrubbing is not practically interactive, regenerate from the same normalized artifacts at a lower mask cadence (5 FPS, then 2 FPS, then 1 FPS) without rerunning inference; retain the smallest cadence that preserves the two QA overlays. Human approval is required before reducing it below 5 FPS for an accepted core method.
- Mark method coverage, chunk boundaries, reinitializations, skipped frames, and errors on the Rerun timeline. A method that only completes the smoke window is visible in the ledger as `smoke_only`; it is not overlaid as a full-result method.
- Pin two review timestamps in the clip manifest: one representative easy manipulation and one failure-stressing moment. These give the human review checkpoints without discarding evidence from the remaining duration.
- Preserve the source/license notice in `SOURCES.md` and the viewer’s text panel. Do not distribute the raw data or an optional capture until the relevant dataset and model terms are re-checked for its intended venue.

## Seven-session execution order
1. **AI-driven:** initialize Git and the `.gitignore`, bootstrap the Python 3.12 project, provenance-file templates, clip/method-manifest templates, fixture schema, ignored artifacts, and a blank pinned-version Rerun recording/Blueprint from synthetic data. **G1:** human selects the three-minute source segment, RGB-static/monochrome-ego view pair, per-toy vocabulary, and intended audience before real data enters the experiment.
2. **AI-driven:** fetch the approved full recordings, generate their canonical 30 FPS trimmed proxies, record source offsets and all clock mappings, and verify synchronization in Rerun. **G2:** human freezes the clip manifest and baseline prompts/settings; subsequent changes require a new run ID.
3. **AI-driven:** integrate MuggledSAM on the smoke window, then continuously track its full-duration two-view target while checkpointing state/output without forced resets; export masks/tracks, profile it, and prepare the shared recording layer.
4. **AI-driven:** integrate MediaPipe Hands on the full-duration RGB static view; show its keypoints against MuggledSAM on the same timeline. CPU-only preprocessing and MediaPipe execution may overlap with GPU work, but GPU methods remain serial. **G3:** human performs one core-spine review from the fixed contact sheet and confirms that 2D joints, boxes, masks, primary/static, and stress-test/ego roles are labeled accurately.
5. **AI-driven, exploratory:** attempt BoxMOT only with independent detections, and CLIP + Drop-DTW only with the explicitly declared GT transcript; add runtime/VRAM panels. Record successful, partial, and blocked outcomes in the ledger without promoting them to core results.
6. **AI-driven, time-boxed:** attempt WiLoR and then exploratory methods in priority order, regenerating the RRD after each accepted full-duration adapter. **G4:** stop at 90 minutes for a new adapter, two hours for Kineo, or immediately after the specified OOM/semantic-misalignment conditions; the human decides whether any retry earns more time.
7. **AI-driven:** run fixture and full-duration smoke checks, populate the five-measure scorecard, verify full-cadence points/boxes plus 5 FPS mask logging, then inspect both review timestamps and several random points in the full timeline. **G5:** human completes the two-timestamp QA, verifies claims and credits/licenses, and approves the final “works/fails” ledger; present exploratory/blocked methods as such rather than trying to demonstrate them.

## Definition of done
- One pinned three-minute Assembly101 segment opens in a single Rerun `.rrd` with continuous MuggledSAM masks/tracks for both target views and MediaPipe hand keypoints for the RGB static view. The 30 FPS analysis proxy is traceable to 60 FPS source video, 30 FPS annotations, and optional 60 FPS pose data. Any BoxMOT or Drop-DTW result remains clearly labeled exploratory; WiLoR is integrated only if the core comparison spine is already usable, and Kineo remains a documented final exploratory outcome.
- Every completed method has preserved native artifacts, normalized data, a run manifest, GPU/runtime profile, and a method-ledger entry.
- The repository can run fixture tests and recreate the viewer without downloading data, while documented real-run commands reproduce the on-disk comparison on the 16GB GPU.
- The method ledger reports the five pre-accuracy measures for every attempted method, and the human QA record contains the same easy and hard timestamp for each completed one.
- The complete Rerun timeline visibly marks successful overlays, chunk boundaries, coverage gaps, and at least one limitation. It logs each encoded source video once, full-cadence points/boxes, and 5 FPS masks while full native masks remain in on-disk artifacts.
